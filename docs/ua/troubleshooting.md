# Вирішення проблем і поширені запитання

Ця сторінка допомагає діагностувати поширені проблеми. У кожному розділі наведено симптом, імовірну причину та спосіб усунення. Якщо документація суперечить коду, правий код; файли, які є джерелом істини, перелічено в [docs/README.md](README.md).

## Встановлення

### Windows SmartScreen або Defender попереджає про інсталятор

Elyra 0.5.0 не підписана кодом за допомогою сертифіката EV, тому Windows може показати "Unknown publisher" або запит SmartScreen.

1. Переконайтеся, що файл походить з офіційної [сторінки випусків](https://github.com/imtiredwhenitalk/Elyra/releases/latest).
2. Перевірте контрольну суму SHA-256:

   ```powershell
   Get-FileHash .\Elyra-latest-x64.msi -Algorithm SHA256
   Get-Content .\Elyra-latest-x64.msi.sha256
   ```

3. Якщо хеші збігаються, виберіть **More info → Run anyway**. Якщо ні — видаліть файл і завантажте його знову.

Ніколи не обходьте попередження для файлу, контрольну суму якого не можете перевірити.

### MSI запитує підтвердження адміністратора

`Elyra-latest-x64.msi` — це пакет Windows Installer для всієї системи (per-machine), тому він може запитувати підвищення прав. Якщо підвищити права неможливо, використайте `Elyra-latest-x64-setup.exe`, який підтримує встановлення для одного користувача.

### Лаунчер не може завантажити MSI

- Перевірте, чи є доступ до GitHub Releases з вашої мережі. Типово лаунчер повторює спроби до трьох разів (змінити це можна через `--retries <n>`).
- Натомість вкажіть локальний файл: `Elyra-Launcher-x64.exe --msi C:\path\Elyra-latest-x64.msi`.
- Вкажіть URL дзеркала: `Elyra-Launcher-x64.exe --url https://example.com/Elyra-latest-x64.msi`. Звичайний HTTP відхиляється, якщо не додати `--allow-insecure-http`.
- Лаунчер записує завантаження до `%TEMP%\elyra-installer\` і продовжує з файлу `.part`. Щоб видалити застарілі передачі, запустіть `Elyra-Launcher-x64.exe cleanup`.
- Якщо контрольну суму опубліковано, але вона не збігається, лаунчер відмовляється встановлювати. Завантажте MSI і супровідний файл `.sha256` разом.
- Додайте `--require-checksum`, якщо потрібно, щоб лаунчер відхиляв будь-який інсталятор без опублікованої контрольної суми.

### `msiexec` зазнає помилки під час встановлення

Запустіть MSI вручну, щоб побачити помилку Windows Installer:

```powershell
msiexec /i .\Elyra-latest-x64.msi /passive /norestart
```

Поширені причини — наявне встановлення в некоректному стані, очікуване перезавантаження або групова політика. Спочатку видаліть попередню версію, перезавантажте комп'ютер і спробуйте знову.

### Видалення не видалило мою пошту

Це навмисно. Видалення зберігає локальну базу поштової скриньки, щоб випадкове видалення не знищило пошту. Щоб видалити все, скористайтеся додатковим очищенням у лаунчері:

```powershell
.\Elyra-Launcher-x64.exe uninstall --backup-data C:\Elyra-backup --remove-data
```

`--remove-data` видаляє `%LOCALAPPDATA%\com.elyra.desktop` та записи Elyra у **Windows Credential Manager**. Спочатку перегляньте дії за допомогою `--dry-run` і зберігайте теку `--backup-data`, доки не впевнитеся, що пошта більше не потрібна. Без цього пражця видаліть теку вручну.

## Перший запуск і вхід

### Вікно початкового налаштування з'являється знову

Вибір "Continue offline" зберігає `elyra-onboarding-skipped` у `localStorage` вебперегляду. Якщо сховище очищено або заблоковано, прапорець втрачається. Увійдіть або знову виберіть **Continue offline**. У десктопній збірці очищення даних застосунку також видаляє цей прапорець.

### Реєстрація не вдається через помилку пароля

Сервер вимагає щонайменше 12 символів. Відображуване ім'я має бути непорожнім і не довшим за 120 символів. Електронна адреса має містити `@` і бути не довшою за 320 символів.

### Реєстрація не вдається з `409 conflict`

Та сама нормалізована електронна адреса вже зареєстрована. Увійдіть або використайте іншу адресу. Регістр літер і пробіли по краях ігноруються, тому `User@example.com` і `user@example.com` — один обліковий запис. Під час оновлення застарілі дублікати потрібно об'єднати перед створенням унікального індексу.

### Вхід не вдається з `invalid credentials`

- Перевірте пароль.
- Перевірте, чи вказано сервер, на якому міститься обліковий запис. Локальний і продакшен-сервер мають окремі бази даних.
- Якщо на сервері змінився `ELYRA_JWT_SECRET`, наявні токени недійсні, але паролі працюють; увійдіть знову.

### Застосунок не може з'єднатися з сервером

- Відкрийте **Settings → Elyra Cloud** і перевірте URL-адресу сервера.
- У продакшені адреса має містити шлях API: `https://mail.example.com/api` без кінцевої похилої риски.
- Перевірте сервер:

  ```powershell
  curl.exe -fsS https://mail.example.com/api/health
  ```

- Перевірте перевизначення в десктопі: змінна оточення `ELYRA_API_URL` має пріоритет над збереженим налаштуванням.
- Локальний сервер типово використовує `http://127.0.0.1:8787` і має бути запущеним.

### Система виходить із облікового запису через деякий час

Токени доступу закінчуються через `ELYRA_ACCESS_TOKEN_TTL_HOURS` (типово 24 години). У версії 0.5.0 немає токенів оновлення, тому увійдіть знову. Зміна `ELYRA_JWT_SECRET` негайно анулює всі токени.

## Поштові облікові записи та IMAP

### Gmail відхиляє мій пароль

Gmail вимагає дворівневої перевірки та **пароля застосунку** для входу за паролем через IMAP. Звичайний пароль облікового запису відхиляється. Створіть пароль застосунку в обліковому записі Google і вставте його в Elyra або налаштуйте `ELYRA_GOOGLE_CLIENT_ID` і скористайтеся входом через OAuth 2.0. Див. [OAuth провайдерів](oauth.md).

### Outlook або Microsoft 365 відхиляє вхід

У багатьох організаціях базову автентифікацію IMAP вимкнено або потрібна згода адміністратора організації. Перевірте налаштування IMAP своєї організації: якщо дозволено, використайте пароль застосунку або налаштуйте `ELYRA_MICROSOFT_CLIENT_ID` і скористайтеся входом через OAuth 2.0. Адміністратор може ще мати надати потрібну область доступу IMAP. Див. [OAuth провайдерів](oauth.md).

### iCloud або Yahoo відхиляє вхід

Обидва вимагають паролів, призначених для застосунків. Створіть такий пароль у налаштуваннях безпеки облікового запису провайдера та використовуйте його замість основного пароля.

### Proton Mail не може підключитися

Proton не надає стандартний IMAP безпосередньо. Встановіть **Proton Mail Bridge**, увійдіть у нього й тримайте його запущеним. Пресет Proton в Elyra використовує `127.0.0.1`; введіть облікові дані IMAP/SMTP від Bridge, а не пароль свого облікового запису Proton.

### Перевірка з'єднання не вдається, хоча налаштування правильні

- Використовуйте TLS на порту 993 для IMAP і 465 для SMTP або STARTTLS на 143/587, якщо провайдер його підтримує. Відкритий текст не підтримується.
- Деякі мережі блокують порти IMAP/SMTP. Спробуйте іншу мережу.
- Корпоративні проксі та перевірка TLS можуть порушувати валідацію сертифікатів.
- Перевірте ім'я користувача. Деякі провайдери вимагають повну адресу, інші — ні.

### Синхронізація нічого не імпортує

- Натисніть **Sync** для конкретного облікового запису. Кнопка оновлення у верхній панелі не звертається до IMAP.
- У версії 0.5.0 синхронізується лише **INBOX** провайдера. Папки Sent, Drafts, Archive, Spam і Trash не завантажуються.
- Перевірте рядок облікового запису на наявність помилки синхронізації. Діагностика не показує помилки для окремих облікових записів.
- Десктопний застосунок типово запитує 40 повідомлень. Якщо потрібно більше, використайте `sync_email_account` із більшим лімітом (до 200), але інтерфейс використовує 40.

### Синхронізація створила дублікати

Синхронізація виконує upsert за `(account_id, provider_id)`, тому повторні синхронізації не повинні створювати дублікати. Дублікати зазвичай означають, що ту саму поштову скриньку додано двічі як два окремі облікові записи. Видаліть один із них.

### Мій стан «прочитано» або «із зіркою» було перезаписано

Локальні значення `is_read` і `is_starred` зберігаються між синхронізаціями. Якщо стан виглядає неправильним, переконайтеся, що не редагуєте той самий лист через два облікові записи.

### Видалення облікового запису видалило локальні повідомлення

Це задокументована поведінка. Видалення облікового запису видаляє його запис у keychain і локально кешовані повідомлення. Якщо потрібна копія, спочатку експортуйте поштову скриньку.

## Надсилання

### Надсилання не вдається з помилкою "SMTP setting ... is not configured"

Не вибрано обліковий запис для надсилання, а резервні змінні оточення `ELYRA_SMTP_*` заповнено не повністю. Виберіть поштовий обліковий запис у compose, налаштуйте всі змінні `ELYRA_SMTP_FROM`, `ELYRA_SMTP_HOST`, `ELYRA_SMTP_USERNAME` і `ELYRA_SMTP_PASSWORD` або увійдіть до Elyra Cloud, щоб використовувати ретрансляцію.

### Надсилання не вдається з помилкою "Elyra Cloud relay failed"

- Переконайтеся, що ви увійшли в систему й токен не закінчився.
- Перевірте `GET {api}/v1/mail/status`; якщо `configured` має значення false, адміністратор сервера не ввімкнув ретрансляцію.
- Ретрансляція повертає `mail_not_configured` (503) або `mail_delivery_failed` (502) з повідомленням. Попросіть адміністратора перевірити журнали сервера та облікові дані SMTP.

### Лист надіслано, але одержувач бачить адресу ретранслятора

Для пошти через ретранслятор це очікувано. Сервер надсилає з адреси `ELYRA_SMTP_FROM` і встановлює `Reply-To` на адресу вашого облікового запису Elyra. Відповіді мають повертатися до вас, якщо сервер і провайдер одержувача враховують `Reply-To`.

### Невдала відправка відсутня у Sent

Невдалі відправки не записуються у **Sent**. У версії 0.5.0 вони зберігаються в локальній черзі вихідних повідомлень, тому їх можна повторити або скасувати через **Settings → Sync & offline**. Після виправлення налаштувань облікового запису або ретрансляції надішліть повідомлення з черги повторно.

### У черзі вихідних повідомлень є заблоковані листи

Повідомлення позначається заблокованим після п'яти невдалих спроб. Перевірте збережену помилку, усуньте причину проблеми з SMTP або ретрансляцією, а потім виберіть **Retry**, щоб скинути лічильник спроб. **Discard** остаточно видаляє повідомлення з черги на цьому пристрої.

### Режим "Work offline" увімкнено, але повідомлення були надіслані

Вимкніть **Work offline** і виконуйте надсилання з черги лише тоді, коли справді цього хочете. Поки перемикач увімкнено, `flush_outgoing_queue` пропускає всі повідомлення в черзі.

### Чернеток немає у провайдера

У версії 0.5.0 чернетки — це локальні записи SQLite. Вони не синхронізуються з IMAP.

## Сповіщення та хмарні функції

### Дзвіночок нічого не показує

Для сповіщень потрібні активна сесія Elyra Cloud і доступний сервер. Список повертає до 100 сповіщень для поточного облікового запису. Сповіщення інших користувачів ніколи не відображаються.

### Надсилання сповіщення повертає `404 not_found`

Адреса одержувача має належати наявному обліковому запису Elyra на тому самому сервері. Сповіщення — це записи всередині застосунку, а не електронні листи.

### Сповіщення на робочому столі не з'являються, коли застосунок закрито

Налаштування **Desktop notifications** лише зберігає вподобання. У версії 0.5.0 хмарні сповіщення з'являються у спливному вікні застосунку. Фонового каналу push-сповіщень немає.

### Вихід із облікового запису не видалив мою пошту

Вихід видаляє хмарну сесію з keychain і сесію в пам'яті. Він не зачіпає локальну пошту та паролі поштових облікових записів.

## Дані та налаштування

### Де розташована база даних?

У Windows: `%LOCALAPPDATA%\com.elyra.desktop\elyra.sqlite3`. Точний шлях показано у **Settings → Diagnostics**.

### Налаштування не зберігаються

Десктопні збірки зберігають налаштування у SQLite. Якщо базу даних не вдалося відкрити, інтерфейс може перейти до сховища браузера або типових значень. Перевірте у Diagnostics шлях до бази, її розмір і версію SQLite, а також права доступу до файлів у `%LOCALAPPDATA%\com.elyra.desktop`.

### "Database is locked" або застосунок зависає під час запуску

Закрийте всі вікна Elyra, потім перевірте наявність залишкового процесу в диспетчері завдань. Режим WAL дозволяє одночасне читання, але два записувачі все одно конфліктують. Якщо файл пошкоджено, створіть резервні копії `elyra.sqlite3` і файлів `-wal`/`-shm`, а потім почніть з нової бази даних.

### Скидання демо-поштової скриньки знищило справжні повідомлення

**Reset demo mailbox** видаляє вкладення та листи перед повторним заповненням демоданими. Це руйнівна дія. Відновіть дані з резервної копії; скасування немає.

### Експорт містить конфіденційні дані

`export_mailbox` повертає тіла повідомлень і метадані у форматі JSON. Зберігайте експорт так само обережно, як і саму поштову скриньку.

### Security Lab повідомляє "Decryption failed"

Це очікуваний результат для неправильного ключа, змінених даних, неправильного base64 або урізаних даних. Згенеруйте ключ, зашифруйте дані, а потім розшифруйте тим самим ключем. Ключі зберігаються лише в пам'яті й втрачаються після перезапуску застосунку.

## Попередній перегляд у браузері

### Деякі кнопки в браузері нічого не роблять

Браузерний попередній перегляд використовує резервний варіант на `localStorage` і навмисно не задіяє Rust, SQLite, keychain, IMAP, SMTP або криптографію. Для справжнього десктопного середовища використовуйте `npm.cmd run tauri dev`.

### Попередній перегляд показує інші дані, ніж застосунок

Попередній перегляд використовує `elyra-fallback:mailbox-v2` і `elyra-fallback:settings-v1` у `localStorage`. Десктопний застосунок використовує SQLite. Це окремі сховища.

## Збірка та розробка

### `npm` заблоковано політикою виконання PowerShell

Явно використовуйте обгортку команд:

```powershell
npm.cmd install --prefix apps/desktop
npm.cmd run check
npm.cmd run build
```

### `cargo` або `rustc` не знайдено

Встановіть Rust з <https://rustup.rs>, а потім знову відкрийте термінал. У Windows встановіть Microsoft C++ Build Tools з робочим навантаженням **Desktop development with C++** та цільовою платформою `x86_64-pc-windows-msvc`.

### Збірка десктопної версії зазнає помилок WebView2

Встановіть WebView2 Runtime. Він постачається з поточними Windows 10/11, але може бути відсутнім на обрізаних або старих образах системи.

### `cargo check -p tauri-app` зазнає помилки, але сервер збирається

Десктопний крейт має залежності лише для Windows (зокрема `keyring` із функцією `windows-native`). Використовуйте інструментарій Windows для десктопного крейта. CI збирає його на `windows-latest`.

### `Cargo.lock` схоже на застарілий

Файл блокувань може відставати від залежностей робочого простору. CI та Docker вирішують залежності без `--locked`. Щоб згенерувати його знову:

```powershell
cargo update -w
git add Cargo.lock
```

### Робочий процес випуску не опублікував артефакти

- Робочий процес запускається за тегами, що відповідають `v*`, або вручну.
- Перевірте крок **Collect release assets** на наявність відсутніх шляхів до пакетів.
- Очікувані артефакти: `Elyra-latest-x64.msi`, `Elyra-latest-x64-setup.exe`, `Elyra-Launcher-x64.exe`, `Elyra-latest-x64.msi.sha256`.
- Якщо збірка Rust зазнала помилки, випуск зупиняється. Спочатку перевірте журнал робочого процесу.

### Вебсайт не оновився

GitHub Pages розгортає `web/` при пуші до `main`. Перевірте робочий процес **Deploy GitHub Pages** та оточення Pages. Кешування в браузері використовує короткочасні заголовки; за потреби зробіть примусове оновлення (hard refresh).

## Сервер і розгортання

### Сервер завершується під час запуску з `ELYRA_JWT_SECRET is not configured`

Вкажіть секрет завдовжки щонайменше 32 символи. Без нього сервер відмовляється запускатися. Згенеруйте його за допомогою `openssl rand -hex 32`.

### Сервер завершується з `ELYRA_SMTP_FROM is required`

Встановлено `ELYRA_SMTP_HOST`, що вмикає ретрансляцію, але адресу відправника не вказано або вона неправильна. Вкажіть коректну `ELYRA_SMTP_FROM` або очистіть `ELYRA_SMTP_HOST`, щоб вимкнути ретрансляцію.

### API не може підключитися до PostgreSQL

- Перевірте `DATABASE_URL`.
- У Compose перевірте `POSTGRES_PASSWORD`, `POSTGRES_USER` і `POSTGRES_DB`.
- Дочекайтеся перевірки стану PostgreSQL; API залежить від неї.
- Перегляньте журнали:

  ```sh
  docker compose --env-file infrastructure/deployment/.env.prod \
    -f infrastructure/deployment/docker-compose.prod.yml logs --tail=100 api
  ```

### `deploy.sh` зазнає помилки одразу

- Переконайтеся, що встановлено Docker Engine 24+ і плагін Compose.
- Переконайтеся, що `.env.prod` існує й доступний для читання.
- Запустіть `./infrastructure/deployment/deploy.sh --check`, щоб перевірити конфігурацію без збірки.

### HTTPS не працює з Caddy

- Запис DNS `A`/`AAAA` уже має вказувати на сервер.
- Порти 80 і 443 мають бути доступні з інтернету.
- `ELYRA_DOMAIN` має бути вказаний і відповідати імені в сертифікаті.
- Перегляньте журнали Caddy:

  ```sh
  docker compose --env-file infrastructure/deployment/.env.prod \
    -f infrastructure/deployment/docker-compose.prod.yml --profile tls logs --tail=100 caddy
  ```

### Десктопний застосунок отримує 404 від сервера

Публічна базова адреса API має містити `/api` і не мати кінцевої похилої риски: `https://mail.example.com/api`. Nginx проксує `location /api/` на `http://api:8787/` і видаляє префікс. URL без `/api` потрапляє на статичний сайт.

### Ретрансляція повертає `mail_delivery_failed`

Перевірте хост SMTP, порт, режим захисту, ім'я користувача та пароль. Використовуйте `tls` на порту 465 або `starttls` на 587. Переконайтеся, що провайдер дозволяє адресу відправника й налаштовано SPF/DKIM/DMARC. Перегляньте журнали API, щоб побачити першопричину помилки.

### Реєстрація відкрита для всіх

Це відоме обмеження версії 0.5.0. Перед відкритим доступом до сервера додайте список дозволених адрес на зворотному проксі, код запрошення або підтвердження адміністратором. Див. [Безпека → Відомі прогалини](security.md#known-gaps-and-follow-ups).

### Ретрансляцію можуть використовувати зловмисно

У версії 0.5.0 немає обмежень частоти чи квот для окремих користувачів. Вимкніть `ELYRA_SMTP_HOST`, доки не додасте обмеження частоти, або обмежте коло тих, хто може реєструватися.

### Резервне копіювання не вдається

Виконайте задокументовану команду `pg_dump` і переконайтеся, що теку `backups/` можна записувати. Копіюйте резервні копії поза сервер і періодично перевіряйте відновлення. Нові дампи створюються за допомогою `pg_dump --clean --if-exists`; відновлюйте їх у порожню базу командою `psql -v ON_ERROR_STOP=1`. Якщо старий дамп зазнає помилки `relation already exists`, почніть із порожньої бази. Див. [Розгортання → Резервні копії](deployment.md#backups) та [чеклист перевірки у продакшені](deploy/VERIFY.md).

### Тести сервера з базою даних пропускаються

`cargo test -p elyra-server` запускає чисті модульні тести без PostgreSQL, але API-тести й тести схеми з базою даних пропускаються, якщо `ELYRA_TEST_DATABASE_URL` не вказує на тимчасову базу. Задайте її явно, щоб побачити можливі помилки. Див. [Конфігурація → Тести сервера](reference/configuration.md#server-tests).

### Автоматичне розгортання не запустилося

Робочий процес `Deploy server` вимкнено, якщо змінна репозиторію `ELYRA_DEPLOY_ENABLED` не дорівнює точно `true`; також мають бути налаштовані секрети `ELYRA_DEPLOY_*`. Він запускається лише за відповідними шляхами або вручну.

## Чеклист діагностики

Повідомляючи про проблему, додайте:

1. Версію Elyra з **Settings → Diagnostics**.
2. Версію та архітектуру Windows або Linux.
3. Точний текст помилки або сповіщення (toast).
4. **Settings → Diagnostics & privacy → Export diagnostic report**. Події маскуються перед збереженням, але перед надсиланням файлу перевірте його: він усе одно містить локальні лічильники, шляхи та метадані повідомлень.
5. Чи виникає проблема в десктопному застосунку, браузерному попередньому перегляді або в обох.
6. Для проблем із сервером: `docker compose ps`, останні журнали API та вивід `curl -fsS https://<domain>/api/health`.
7. Для проблем з IMAP: провайдер, хост, порт і режим захисту. Ніколи не додавайте свій пароль.
