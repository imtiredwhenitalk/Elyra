# Довідник з конфігурації

Усі змінні, що використовуються Elyra 0.4.0 під час виконання, збирання та
розгортання, зібрані в одному місці.

Умовні позначення: **Обов'язково** означає, що без неї компонент не працює або
функція не доступна. Значення враховують регістр.

<a id="desktop-api-url"></a>
## URL API десктопного застосунку

Десктопний застосунок визначає базовий URL сервера Elyra в такому порядку:

1. Змінна середовища `ELYRA_API_URL` (середовище процесу).
2. SQLite `settings.api_url`, який встановлюється через **Налаштування → Elyra Cloud → URL сервера**.
3. `ELYRA_DEFAULT_API_URL`, вбудований до інсталятора під час збирання.
4. `http://127.0.0.1:8787`.

Кінцеві похилі риски видаляються. URL має починатися з `http://` або `https://`.
У виробничих URL обов'язково має бути `/api`, наприклад
`https://mail.example.com/api`.

| Змінна | Область застосування | Обов'язково | Примітки |
| --- | --- | --- | --- |
| `ELYRA_API_URL` | Під час виконання десктопного застосунку | Ні | Перевизначає збережене налаштування; корисно для розробки |
| `ELYRA_DEFAULT_API_URL` | Під час збирання | Ні | Вбудовується до інсталяторів випусків робочим процесом випуску |
| `settings.api_url` | Налаштування SQLite | Ні | Керується застосунком; не є змінною середовища |

## Резервний SMTP десктопного застосунку

Коли у файлі створення листа не вибрано обліковий запис, десктопний застосунок
спочатку пробує SMTP із середовища, а потім — хмарний ретранслятор. Щоб цей шлях
працював, мають бути задані всі чотири обов'язкові значення.

| Змінна | Обов'язково для резервного варіанта | Типове значення | Примітки |
| --- | --- | --- | --- |
| `ELYRA_SMTP_FROM` | Так | — | Адреса відправника; має бути коректною електронною адресою |
| `ELYRA_SMTP_HOST` | Так | — | Хост SMTP |
| `ELYRA_SMTP_USERNAME` | Так | — | Ім'я користувача SMTP |
| `ELYRA_SMTP_PASSWORD` | Так | — | Пароль SMTP або пароль застосунку |
| `ELYRA_SMTP_PORT` | Ні | `587` | Порт |

Резервний варіант із середовища в десктопному застосунку використовує STARTTLS
(`starttls_relay`). Для неявного TLS натомість налаштуйте поштовий обліковий
запис. Якщо `ELYRA_SMTP_FROM` не містить відображуваного імені, типово
використовується `Alex Smith`.

<a id="provider-oauth"></a>
## Ідентифікатори клієнта OAuth провайдерів

Потік OAuth у десктопному застосунку є публічним нативним клієнтом: клієнтського
секрету немає. Ідентифікатор клієнта все одно потрібен для кожного провайдера,
який ви хочете запропонувати. Вкажіть його під час збирання (`option_env!`) або в
середовищі процесу; значення під час виконання має вищий пріоритет.

| Змінна | Область | Обов'язково | Примітки |
| --- | --- | --- | --- |
| `ELYRA_GOOGLE_CLIENT_ID` | Збирання або виконання десктопного застосунку | Для OAuth Gmail | Публічний ідентифікатор OAuth; зареєструйте клієнт Desktop/Native |
| `ELYRA_MICROSOFT_CLIENT_ID` | Збирання або виконання десктопного застосунку | Для OAuth Outlook | Публічний ідентифікатор клієнта Microsoft identity |

Без ідентифікатора клієнта модальне вікно приховує кнопку OAuth цього
провайдера, а `oauth_start` повертає помилку налаштування. Див. [OAuth
провайдерів](../oauth.md).

Це рядки «ключ — значення» у локальній таблиці `settings`. Ними керує
інтерфейс застосунку, а не змінні середовища.

| `accent` | `moss` | `moss`, `ocean`, `ember`, `violet` |
| `density` | `comfortable` | `comfortable`, `compact` |
| `display_name` | `Alex Smith` | Ім'я локального профілю |
| `domain_handle` | `alex@elyra.com` | Прототип ідентифікатора Elyra лише для відображення |
| `signature` | `Sent from Elyra` | Попереднє заповнення під час створення листа |
| `local_only` | `true` | Налаштування з пріоритетом локальної роботи |
| `desktop_notifications` | `true` | Збережене налаштування сповіщень |
| `reduce_motion` | `false` | Вимикає несуттєву анімацію |
| `auto_priority` | `true` | Застосовує локальні пропозиції пріоритету під час імпорту; `false` використовує `priority_default` |
| `priority_default` | `normal` | `low`, `normal`, `high` або `urgent` — початковий пріоритет, коли пропозиції вимкнено |
| `blocked_sender_action` | `spam` | Куди поміщати листи, що відповідають правилу блокування відправника: `spam` або `trash` |
| `attachment_scanning` | `true` | Класифікує вкладення під час імпорту |
| `attachment_clamav` | `false` | Запускає локальний ClamAV для вмісту збережених вкладень |
| `attachment_virustotal` | `false` | Дозволяє завантажувати файли до VirusTotal за згодою користувача |
| `clamav_path` | `clamscan` | Назва виконуваного файлу або повний шлях до `clamscan` |
| `attachment_scan_max_mb` | `25` | Максимальний розмір вкладення, який надсилається до ClamAV або VirusTotal; обмежено діапазоном 1–200 |
| `api_url` | не встановлено | Збережений базовий URL сервера Elyra |
| `last_sync_at` | не встановлено | Час останньої успішної синхронізації облікового запису |
| `diagnostic_logging_enabled` | `true` | Зберігає знеособлені локальні діагностичні події, коли значення `true` |
| `crash_reporting_enabled` | `false` | Лише налаштування; у Elyra 0.4.0 немає кінцевої точки для надсилання звітів |
| `sync_offline_mode` | `false` | Залишає листи в черзі на цьому пристрої й не надсилає повідомлення з пошти вихідних |
| `sync_last_error` | не встановлено | Знеособлена помилка останньої невдалої спроби надсилання |
| `external_scanning` | `true` | Встановіть `false`, щоб вимкнути запити до VirusTotal і Google Safe Browsing |
| `cloud_session` | застаріле | Під час першого читання переноситься до ключниці, після чого видаляється |

Попередній перегляд у браузері також використовує ключі `localStorage`:

- `elyra-onboarding-skipped` — приховування модального вікна початкового налаштування.
- `elyra-security-preferences` — налаштування Security Lab.
- `elyra-fallback:mailbox-v2` — дані поштової скриньки для попереднього перегляду.
- `elyra-fallback:settings-v1` — налаштування для попереднього перегляду.
- `elyra-fallback:message-security-v1` — результати Shield для попереднього перегляду.
- `elyra-fallback:crypto-keys-v1` — ключі ідентифікації для попереднього перегляду (без приватних даних).
- `elyra-fallback:crypto-contacts-v1` — відкриті ключі контактів для попереднього перегляду.
- `elyra-fallback:integrations-v1` — стан інтеграцій для попереднього перегляду. Ключі API
  для попереднього перегляду зберігаються лише в пам'яті та не записуються до
  `localStorage`.
- `elyra-fallback:sender-rules-v1` — правила блокування та дозволу відправників для попереднього перегляду.
- `elyra-fallback:reputation-v1` — репутація доменів відправників для попереднього перегляду.
- `elyra-fallback:diagnostics-v1` — діагностичні події для попереднього перегляду (знеособлені).
- `elyra-fallback:outbox-v1` — вихідні повідомлення в черзі для попереднього перегляду.

<a id="server"></a>
## Сервер

Змінні завантажуються з середовища процесу, а під час розробки — з `server/.env`
через `dotenvy`.

| Змінна | Обов'язково | Типове значення | Примітки |
| --- | --- | --- | --- |
| `DATABASE_URL` | Так | — | Рядок підключення до PostgreSQL; максимальний розмір пулу — 10 |
| `ELYRA_JWT_SECRET` | Так | — | Не менше 32 символів; інакше сервер відмовляється запускатися |
| `ELYRA_SERVER_ADDR` | Ні | `127.0.0.1:8787` | У виробничому середовищі Docker встановлює `0.0.0.0:8787` |
| `ELYRA_ACCESS_TOKEN_TTL_HOURS` | Ні | `24` | Термін дії JWT у годинах |
| `RUST_LOG` | Ні | `elyra_server=info,tower_http=info` | Фільтр трасування |
| `ELYRA_SMTP_HOST` | Ні | порожньо | Порожнє значення вимикає ретранслятор |
| `ELYRA_SMTP_PORT` | Ні | `587` для STARTTLS, `465` для TLS | Порт SMTP |
| `ELYRA_SMTP_SECURITY` | Ні | `starttls` | `tls` або `starttls`; будь-яке інше значення стає `starttls` |
| `ELYRA_SMTP_USERNAME` | Ні | порожньо | Ім'я користувача ретранслятора |
| `ELYRA_SMTP_PASSWORD` | Ні | порожньо | Пароль ретранслятора |
| `ELYRA_SMTP_FROM` | Коли ретранслятор увімкнено | — | Має бути коректною поштовою адресою; відсутня або некоректна адреса блокує запуск |
| `ELYRA_SMTP_FROM_NAME` | Ні | `Elyra` | Відображуване ім'я в листах, надісланих через ретранслятор |

### Правила запуску ретранслятора

- `ELYRA_SMTP_HOST` порожній або містить лише пробіли → ретранслятор вимкнено, без помилки.
- `ELYRA_SMTP_HOST` задано, `ELYRA_SMTP_FROM` відсутній → помилка запуску.
- `ELYRA_SMTP_HOST` задано, `ELYRA_SMTP_FROM` некоректний → помилка запуску.
- `ELYRA_SMTP_SECURITY=tls` → неявний TLS.
- Будь-яке інше значення параметра безпеки → STARTTLS.

### Тести сервера

| Змінна | Обов'язково | Типове значення | Примітки |

| `ELYRA_TEST_DATABASE_URL` | Ні | не встановлено | URL PostgreSQL для тестів із базою даних. Без нього тести БД пропускаються; за його наявності помилки повідомляються |

Запустіть `cargo test -p elyra-server`. Чисті модульні тести завжди

перевірити міграції схеми, послідовності API та обмеження PostgreSQL.

### deploy.sh

| Змінна | Типове значення | Примітки |
| --- | --- | --- |
| `ELYRA_ENV_FILE` | `infrastructure/deployment/.env.prod` | Альтернативний шлях до файлу середовища |

Для резервних копій використовується `pg_dump --clean --if-exists`, тому
отриманий SQL можна відновити у порожній базі даних за допомогою
`psql -v ON_ERROR_STOP=1`. Повний порядок дій із резервування та відновлення
див. у [`docs/deploy/VERIFY.md`](../deploy/VERIFY.md).

## Вебсайт

Вебсайт є статичним. Він не має змінних середовища під час виконання.

- GitHub Pages обслуговує `web/` безпосередньо.
- Виробничий контейнер Nginx обслуговує `web/` і проксіює `/api/` на
  `api:8787/`.
- Запити до `location = /health` проксіюються на `api:8787/health`.

## Зауваження щодо безпеки

- Ніколи не фіксуйте у Git `.env`, `.env.prod` або справжні секрети.
- Файл `.env.prod` має мати режим доступу `600` і належати користувачеві
  розгортання.
- Зміна `ELYRA_JWT_SECRET` робить усі токени доступу недійсними.
- Після зміни `POSTGRES_PASSWORD` потрібно узгоджено оновити `DATABASE_URL` або
  середовище Compose.
- Якщо облікові дані ретранслятора були розкриті, замініть їх.
- Змінні середовища видимі процесу й можуть потрапити до дампів аварії або
  звітів інспектування контейнерів. Для розгортань із підвищеними вимогами до
  безпеки надавайте перевагу Docker secrets або зовнішньому менеджеру секретів.
