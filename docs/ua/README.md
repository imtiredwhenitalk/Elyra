# Документація Elyra

Це основний набір документації для Elyra **0.5.0**. Він описує те, що проєкт наразі дійсно постачає: клієнт для Windows-робочого стола, побудований на Tauri 2 та Rust, локальну поштову скриньку SQLite, сервер API на Rust/PostgreSQL, додатковий SMTP-релей, портативний засіб запуску та статичний публічний сайт.

Почніть зі сторінки, що відповідає тому, що ви хочете зробити.

## Чим ця документація не є

- Це не обіцянка можливостей, яких не існує. OAuth провайдерів із PKCE реалізовано для синхронізації IMAP у десктопній збірці; SMTP XOAUTH2, оновлення в реальному часі через WebSocket, заплановане фонове синхронізування та шифрування поштових скриньок на диску **не** реалізовані у 0.5.0. Вони вказані як наступні етапи в [task.md](../../task.md).
- Вона не замінює маркерів `ARCHITECTURE.md` у кожному каталозі. Ці файли — короткі нотатки про обсяг для учасників, які працюють у межах каталогу. Набір `docs/` — це наративна документація.

## Домовленості

- Шляхи в репозиторії записуються відносно кореня репозиторію, наприклад
  `apps/desktop/src-tauri/src/mailbox.rs`.
- Команди Windows використовують синтаксис PowerShell (`npm.cmd`, `$env:NAME`). Команди сервера Linux використовують синтаксис POSIX shell.
- «Робочий стіл» означає застосунок Tauri. «Webview» означає шар HTML/CSS/JS усередині нього. «Core» означає код Rust у `apps/desktop/src-tauri`.
- Твердження, позначене як **реалізоване**, підтверджується кодом у цьому репозиторії. Твердження, позначене як **заплановане**, відстежується в `task.md` і ще недоступне.

## Документація як джерело істини

Коли документація й код розходяться, слушний код. Для перевірки поведінки використовуйте ці файли:

| Тема | Джерело істини |
| --- | --- |
| Команди та налаштування робочого стола | `apps/desktop/src-tauri/src/lib.rs` |
| Схема локальної бази даних | `apps/desktop/src-tauri/src/storage.rs`, `mailbox.rs`, `providers.rs` |
| Поведінка хмарного клієнта | `apps/desktop/src-tauri/src/cloud.rs` |
| Потік OAuth провайдерів | `apps/desktop/src-tauri/src/oauth.rs` |
| Надсилання та резервний релей | `apps/desktop/services/sendemail.rs`, `server/src/mailer.rs` |
| HTTP-маршрути та помилки | `server/src/api.rs` |
| Схема сервера | `server/src/database.rs` |
| Виробничі сервіси | `infrastructure/deployment/docker-compose.prod.yml` |
| Конфігурація інсталятора та пакета | `apps/desktop/src-tauri/tauri.conf.json` |
| Конвеєр випуску | `.github/workflows/release.yml`, `.github/workflows/rust.yml` |
| Конвеєр випуску для Linux | `.github/workflows/linux-release.yml`, `packaging/linux/PKGBUILD` |

## Актуальність документації

Зміни в документації не потребують схвалення архітектури, але мають описувати реалізацію такою, яка вона є. Коли ви змінюєте команду, маршрут, змінну середовища, схему або крок розгортання:

1. Оновіть відповідну сторінку в `docs/`.
2. Додайте запис до [`changes.md`](../../changes.md) із маркером `[200 OK]`, який використовує цей проєкт.
3. Оновіть [`task.md`](../../task.md), якщо зміна завершує або додає етап дорожньої карти.
4. Повторно перевірте посилання та блоки коду.
