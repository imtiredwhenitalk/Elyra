# Криптографічний шар Elyra

Криптографічна межа десктопного застосунку розташована у
`apps/desktop/src-tauri/src/crypto.rs`. Код браузера може запитувати операції
через команди Tauri, відкриті у `lib.rs`, але сам ніколи не реалізує
шифрування.

## Поточні гарантії

- Автентифіковане шифрування AES-256-GCM.
- 32-байтові ключі, згенеровані за допомогою `OsRng`.
- Новий 96-бітний nonce для кожної операції шифрування.
- Nonce зберігається як частина корисного навантаження base64; він не є
  секретом.
- Відбитки SHA-256 призначені лише для відображення та порівняння, а не для
  автентифікації.
- Недійсні ключі, коректно не сформовані корисні навантаження, неправильні
  ключі та змінений шифротекст повертають помилки.
- HPKE за RFC 9180 з DHKEM(X25519, HKDF-SHA256), HKDF-SHA256 та AES-256-GCM.
- Типізовані конверти повідомлень із версіями та підписами Ed25519 канонічних
  метаданих конверта й шифротексту.
- Ключі корисного навантаження для отримувачів запечатуються окремо для
  кожного ключа X25519 отримувача.

Поточний Security Lab навмисно зберігає згенеровані ключі у пам'яті та
використовує відоме тестове повідомлення. Для ключів виробничих акаунтів перед
шифруванням даних поштових скриньок у стані спокою все ще потрібна інтеграція
зі сховищем ключів ОС. Ніколи не розміщуйте ключі шифрування у localStorage,
URL-адресах, журналах або вмісті листів.

Запланований протокол E2EE, межі довіри, розділення ключів, перевірка
отримувачів та обмеження прямої секретності визначені у
[`../security/e2ee.md`](../security/e2ee.md).
