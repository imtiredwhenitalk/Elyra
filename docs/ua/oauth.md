# OAuth 2.0 для поштових провайдерів

Elyra може входити до Gmail та Outlook/Microsoft 365 через OAuth 2.0
**Authorization Code + PKCE** замість пароля застосунку IMAP. Це нативний потік
робочого стола: Elyra відкриває системний браузер, слухає тимчасовий порт
loopback і не просить вас вводити клієнтський секрет у застосунок.

> **Обсяг.** OAuth надає дозвіл на **синхронізацію IMAP** через
> `AUTHENTICATE XOAUTH2`. Для вихідного SMTP все ще потрібен пароль застосунку
> або релей Elyra. Див. [Обмеження](#limitations).

<a id="how-it-works"></a>
## Як це працює

1. Elyra генерує випадковий `state` та PKCE `code_verifier` і обчислює
   `code_challenge` методом S256 (RFC 7636).
2. Вона прив'язує `127.0.0.1` до довільного порту й відкриває екран згоди
   постачальника у типовому браузері.
3. Постачальник перенаправляє на `http://127.0.0.1:<port>/callback` із `code`
   та `state`. Elyra відхиляє відповідь, якщо `state` не збігається.
4. Код обмінюється на токен на кінцевій точці з початковим верифікатором.
   Клієнтський секрет не використовується, бо Elyra — публічний нативний клієнт.
5. Рядок облікового запису створюється або оновлюється, а набір токенів
   записується до сховища ключів ОС під ключем `oauth-account-<id>`. SQLite не
   зберігає токенів.
6. Токен доступу оновлюється автоматично до завершення строку дії. Якщо токен
   оновлення відкликано або він прострочений, з'являється зрозуміла порада
   повторно підключити обліковий запис.

<a id="configuration"></a>
## Налаштування

Ідентифікатори клієнтів є публічними, але Elyra не постачає фіктивні значення.
Вкажіть один або обидва ідентифікатори перед збиранням чи запуском десктопного
застосунку:

| Змінна | Коли | Призначення |
| :--- | :--- | :--- |
| `ELYRA_GOOGLE_CLIENT_ID` | Під час збирання або виконання | Клієнт OAuth Gmail/Google |
| `ELYRA_MICROSOFT_CLIENT_ID` | Під час збирання або виконання | Клієнт ідентифікації Microsoft/Outlook |

Значення під час збирання вбудовуються через `option_env!`; значення під час
виконання має вищий пріоритет. У модальному вікні облікового запису
постачальник позначається доступним лише за наявності ідентифікатора клієнта.
У попередньому перегляді у браузері кнопки OAuth приховані — потік потребує
Rust-ядра та ключниці ОС.

Зареєструйте у постачальника клієнт типу **Desktop app / Native** і дозвольте
перенаправлення на loopback `http://127.0.0.1:<port>/callback`. І Google, і
Microsoft дозволяють динамічний порт loopback для нативних клієнтів.
Запитувані області доступу:

| Постачальник | Області |
| :--- | :--- |
| Google | `openid email profile https://mail.google.com/` |
| Microsoft | `openid profile email offline_access https://outlook.office.com/IMAP.AccessAsUser.All` |

<a id="sign-in"></a>
## Вхід у десктопному застосунку

1. Відкрийте **Налаштування → Поштові облікові записи** й виберіть Gmail або
   Outlook.
2. Введіть адресу електронної пошти й збережіть обліковий запис (або одразу
   почніть OAuth із панелі **OAuth 2.0 sign-in (PKCE)**).
3. Клацніть **Увійти через Google / Microsoft** і схваліть екран згоди у
   браузері.
4. Поверніться до Elyra. Рядок облікового запису покаже **OAuth connected**.
5. Клацніть **Синхронізувати**, щоб імпортувати найновіші листи INBOX. Сеанс
   IMAP автентифікується через `AUTHENTICATE XOAUTH2`; локальний стан
   «прочитано»/«зірка» зберігається так само, як для облікових записів із
   паролем.

**Відключити OAuth** вилучає запис із ключниці й повертає обліковий запис до
автентифікації за паролем. Для Google відкликання на сервері відбувається на
найкращих зусиллях; втрата мережі не блокує локальне відключення. Видалення
облікового запису також вилучає його OAuth-токен.

<a id="commands"></a>
## Команди Tauri

| Команда | Аргументи | Повертає |
| :--- | :--- | :--- |
| `oauth_providers` | — | Постачальники з полями `configured`, `scopes`, `docsUrl` |
| `oauth_start` | `provider` (`google`/`microsoft`, також `gmail`/`outlook`), `email` | `OAuthSessionView` без секретів |
| `oauth_status` | `accountId` | Стан підключення, строк дії, наявність токена оновлення |
| `oauth_revoke` | `accountId` | Стан відключення; вилучає локальні токени |

`OAuthSessionView` містить лише `accountId`, `provider`, `email`, `connected`,
`expiresAt`, `hasRefreshToken` та `needsAttention`. Токени доступу й оновлення
ніколи не передаються у webview.

<a id="limitations"></a>
## Обмеження

- **SMTP.** `send_email` для облікового запису OAuth повертає зрозумілу помилку.
  Використовуйте релей Elyra Cloud або збережіть пароль застосунку, щоб
  перейти обліковий запис на автентифікацію за паролем.
  Відстеження: `issues/open/003-oauth-smtp-xoauth2.md`.
- **Немає OAuth-провайдера Elyra Cloud.** Elyra Cloud досі використовує
  реєстрацію/вхід із паролями Argon2 та JWT-токенами доступу. OAuth тут призначений
  лише для сторонніх поштових провайдерів.
- **Попередній перегляд у браузері.** Команди `oauth_*` не реалізовані в
  `services/tauri.js`, тому кнопки не з'являються поза десктопною збіркою.
- **Переносимість згоди.** Зміна зареєстрованого ідентифікатора клієнта або
  відкликання згоди вимагає повторного входу.

<a id="troubleshooting"></a>
## Усунення несправностей

| Симптом | Причина / дія |
| :--- | :--- |
| «… OAuth is not configured» | Вкажіть `ELYRA_GOOGLE_CLIENT_ID` або `ELYRA_MICROSOFT_CLIENT_ID` і перезапустіть/перезберіть застосунок. |
| «OAuth state did not match» | Відповідь прийшла з іншої вкладки або старого запиту. Повторіть вхід, не використовуйте повторно вкладки браузера. |
| «OAuth sign-in timed out» | Протягом 5 хвилин нічого не досягло loopback-слухача. Перевірте, чи браузер може звертатися до `127.0.0.1`. |
| «The OAuth token endpoint returned HTTP …» | Неправильний ідентифікатор клієнта, URI перенаправлення або верифікатор PKCE. Перевірте реєстрацію клієнта у постачальника. |
| «OAuth session expired. Reconnect this account.» | Немає придатного токена оновлення. Увійдіть ще раз. |
| IMAP працює, SMTP — ні | Це очікувано: SMTP XOAUTH2 не реалізовано. Скористайтеся релеєм Elyra або збережіть пароль застосунку, щоб перейти обліковий запис на автентифікацію за паролем. |
