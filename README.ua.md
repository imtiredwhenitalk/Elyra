## Чому Elyra

- **Локальність за замовчуванням.** Для роботи з простором не потрібен обліковий запис. Пошта, налаштування й результати сканування зберігаються в локальній базі SQLite на вашому пристрої.
- **Rust на всіх рівнях.** Запити до поштової скриньки, синхронізація IMAP, надсилання, криптографія, репутація та аналіз вкладень виконуються в ядрі Rust за командами Tauri.
- **Безпека, яку видно.** Кожен вердикт має причину — від репутації відправника до ризику вкладень — а зовнішні перевірки увімкнюються лише за вашою згодою.
- **Інсталятори, яким можна довіряти.** Завантаження використовують стабільні назви файлів і супутні файли SHA-256; оновлення Windows перевіряються на цифровий підпис перед встановленням.
- **Без таємничих серверів.** Webview — це лише шар представлення. Він ніколи не отримує ваші паролі, API-ключі або токени хмарних сеансів.
- **Ваш сервер, якщо хочете.** Готовий Compose-стек для продакшену, скрипт розгортання, контрольний список перевірки та інтеграційні тести бази даних підтримують самостійний хостинг.

## Вбудована безпека

Elyra спочатку перевіряє все локально. Зовнішня аналітика працює лише з вашими власними ключами (BYOK) і ніколи не запускається непомітно.

| Рівень | Що він робить |
| :--- | :--- |
| 🛡️ **Elyra Shield** | Оцінює повідомлення за локальними евристиками фішингу та соціальної інженерії, перевіряє підміну відправника й імені, а також невідповідність видимих посилань. |
| ✅ **Репутація відправника** | Класифікує домени відправників як Довірені, Нейтральні, Підозрілі або Шкідливі, використовуючи правила дозволу й блокування, перевірку брендів, SPF / DKIM / DMARC та кешовану аналітику загроз. |
| 🚫 **Правила для відправників** | Блокує або дозволяє адреси й цілі домени. Правила дозволу завжди мають перевагу, а заблоковані листи можуть потрапляти до Спаму або Кошика. |
| 📎 **Сканування вкладень** | Визначає справжній тип файлу за сигнатурними байтами, позначає виконувані файли, скрипти, образи дисків, документи з макросами, архіви, подвійні розширення та прихований двобічний текст. |
| 🔗 **Аналітика загроз** | Необов'язкові запити до VirusTotal і Google Safe Browsing з вашими власними API-ключами, локальним кешуванням і обмеженням частоти. |
| 🔐 **Криптографія та секрети** | Шифрування AES-256-GCM, ключі ідентичності Ed25519 і збереження секретів у ключниці ОС, де це доступно (наразі Windows Credential Manager; підтримка Linux Secret Service ще вдосконалюється). |

> **Спочатку згода.** Вкладення ніколи не завантажуються до VirusTotal без вашого підтвердження кожного файлу. Файли ніколи не виконуються, не відкриваються й не запускаються автоматично Elyra. ClamAV увімкнюється окремо й працює на цьому пристрої.

## Оновлення та видалення

Збірки для Windows містять **Налаштування → Оновлення**: перевірку на вимогу, відомості про поточну та найновішу версію, нотатки до випуску, прогрес завантаження й перевірки, встановлення, а також налаштування автоматичних перевірок і сповіщень. Публічний ключ оновлень вбудовано в застосунок; невдала перевірка, хибний підпис або помилка завантаження залишають встановлену версію незмінною. Секрети підпису та контрольний список випуску описано в [Оновленнях для робочого столу](docs/ua/desktop-updates.md).

Видалення за замовчуванням не знищує дані. Використовуйте **Налаштування → Програми → Elyra** у Windows або спочатку перегляньте, що прибере завантажувач:

```powershell
.\Elyra-Launcher-x64.exe uninstall --dry-run
```

Додайте `--remove-data` (або `--purge`), щоб видалити локальну базу даних і відповідні записи в ключниці; за потреби з `--backup-data <folder>`. Усі прапорці описано в [Початку роботи](docs/ua/getting-started.md#9-uninstall).

Встановлення на Linux оновлюються заміною AppImage або `.deb` із перевіреною контрольною сумою; видалення пакета не вилучає локальну пошту чи налаштування.

## Збірка з вихідного коду

### Windows

Вимоги: Windows 10/11, Node.js 20+, стабільна версія Rust і попередні умови Tauri 2 (Microsoft C++ Build Tools із робочим навантаженням **Desktop development with C++**).

```powershell
npm.cmd install --prefix apps/desktop
npm.cmd run check
npm.cmd run build        # MSI + NSIS bundles
cargo check -p tauri-app
cargo test -p elyra-crypto -p elyra-server -p elyra-launcher
```

### Linux

Вимоги: дистрибутив Linux із системними бібліотеками Tauri 2 (WebKit2GTK 4.1, GTK 3, AppIndicator), Node.js 20+ і стабільна версія Rust.

```sh
npm install --prefix apps/desktop
npm run check
npm --prefix apps/desktop run tauri -- build --bundles appimage deb
cargo test -p elyra-crypto -p elyra-server -p elyra-launcher
```

Фронтенд статичний (`apps/desktop/src`), тому етапу збирання бандла немає. Резервний режим попереднього перегляду в браузері в `apps/desktop/src/services/tauri.js` залишає інтерфейс працездатним без Tauri, а збірки для робочого столу завжди використовують команди Rust.

Типово тести сервера з базою даних пропускаються, якщо PostgreSQL недоступний. Щоб виконати їх проти тимчасової бази:

```powershell
$env:ELYRA_TEST_DATABASE_URL = "postgres://elyra:elyra@127.0.0.1:5432/elyra_test"
cargo test -p elyra-server
```

Запустіть сервер API командою `cargo run -p elyra-server` після запуску PostgreSQL і копіювання [`server/.env.example`](server/.env.example).

## Архітектура

```text
apps/desktop            Tauri 2 вікно + статичний HTML/CSS/JS
        │
        │ Команди Tauri
        ▼
Ядро Rust               пошта · провайдери · Shield · пріоритет
                        відправники · репутація · вкладення · криптографія
        │
        ├── SQLite      локальна пошта, налаштування, результати сканування
        ├── Keychain    хмарні сеанси, паролі IMAP, OAuth-токени, API-ключі
        └── Updater     підписаний маніфест + перевірені інсталятори Windows

apps/launcher           завантаження → перевірка → встановлення → запуск / видалення
server                  Axum API + PostgreSQL + SMTP-релей (самостійний хостинг)
web                     статичний сайт із маркетингом і завантаженням
```

Робочий простір Rust також містить багаторазово використовуваний пакет [`elyra-crypto`](packages/crypto), сервіс [`server`](server) з автентифікацією та [`launcher`](apps/launcher) для Windows. Сервер використовує PostgreSQL для метаданих облікових записів і курсорів синхронізації, Argon2id для хешування паролів і підписані токени доступу. Він ніколи не отримує локальні ключі шифрування.

Автоматизація випусків розташована в `.github/workflows`: `rust.yml` перевіряє обидві платформи, `release.yml` збирає й підписує файли Windows разом із `latest.json`, `linux-release.yml` збирає AppImage і `.deb`, а `deploy.yml` виконує увімкнюване вручну розгортання API через SSH для самостійного хостингу.

## Локальні дані

На Windows база даних робочого столу розташована за адресою `%LOCALAPPDATA%\com.elyra.desktop\elyra.sqlite3`. На Linux вона лежить у каталозі даних XDG, зазвичай `~/.local/share/com.elyra.desktop/elyra.sqlite3`. Точний шлях показує **Налаштування → Діагностика**. SQLite використовує журналювання WAL, зовнішні ключі та безпечне видалення.

Хмарні сеанси, паролі IMAP, набори OAuth-токенів провайдерів та API-ключі інтеграцій зберігаються в ключниці ОС, а не в базі даних. Видалення застосунку не вилучає їх і не видаляє поштову скриньку, якщо ви явно не попросите про це завантажувач.

## Стан і план розробки

Версія **0.4.0** — поточна лінія випусків. Фаза 1 (Shield, аналітика загроз, ключі ідентичності, інтеграції BYOK), фаза 2 (пріоритет, правила для відправників, репутація, сканування вкладень), фаза 3 (завантажувач і видалення, пакети для Linux, тестування сервера та перевірка продакшену, підписані оновлення Windows) і фаза 4 (локальна діагностика з маскуванням даних, розширений пошук, офлайн-черга надсилання, полірування доступності) реалізовані у гілці `main`; CI для Rust перевіряє Windows і Linux.

У 0.4.0 помилки після маскування записуються локально, розширені фільтри повністю виконуються в SQLite, невдалі надсилання чекають у надійній черзі, а руйнівні дії вимагають підтвердження з доступом із клавіатури. Діагностичні дані не завантажуються автоматично.

OAuth Gmail/Outlook із PKCE доступний для синхронізації IMAP у десктопному застосунку. Далі: SMTP XOAUTH2 для таких облікових записів, фонова синхронізація за розкладом, оновлення в реальному часі через WebSocket і шифрування поштової скриньки на диску. Пакування Flatpak було досліджено й задокументовано, але воно не постачається у 0.4.0.

Слідкуйте за роботою в [`task.md`](task.md), [`changes.md`](changes.md) і локальних файлах [`issues/`](issues/README.md); шаблони для GitHub-записок містяться в [`.github/ISSUE_TEMPLATE/`](.github/ISSUE_TEMPLATE/).

## Участь у розробці

Передумови, команди та домовленості репозиторію описано в [`docs/ua/development.md`](docs/ua/development.md). Коли ви змінюєте команду, маршрут, змінну середовища, схему чи крок розгортання, оновіть відповідну сторінку документації, додайте запис до [`changes.md`](changes.md) і оновіть [`task.md`](task.md), якщо змінився план розробки.
